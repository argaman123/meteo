The catalog→engine render path (committed 2655cbd, 2026-06-30, after a long design session). Shape, and the **rejected alternatives** so they don't get reproposed:

- **`Grid` is a scalar field** (one `Float32Array`, `valueAt → number`, keeps its `param` in `info`) + static **`Grid.combine(grids, fn)`** for derived fields. *Rejected: a multi-component Grid + a per-texel `scalar(components)` extractor on the colormap — the lead wanted Grid scalar and Colormap unaware of multi-value.*
- **Layer kinds (2026-07-15 split, lead-driven):** `Layer<D>` is the generic base (name, looks, timeWindow, `hover(data: D)`, `fetch(on, injector): Signal<D | undefined>`); `ModelLayer extends Layer<Grid[]>` owns `parameters: Parameter[]` (enum in `types/parameter.ts`, values = backend wire names), a `model` signal (plain for now — the first model-picker UI was built then scraped 2026-07-15; the "Generic option controls" pool task re-adds it properly: one control mechanism per control TYPE, cycleOptions shared by model+speed), and builds its own httpResources per parameter (fetch moved OUT of the service into the layer kind). Satellite/radar/observations become sibling kinds with their own data types. `Provider<I>` and `Look<I>` are both source-blind (lead, two rounds: "not a fan of how a look is knowing what the source is", then "why anything at all? why not like before only I?") — Provider's constructor takes `(data: never) => I` (contravariance accepts any annotated fn), `provide(data: unknown)` casts once internally, and each DEFINITION annotates its lambda param (`new Provider((grids: Grid[]) => …)`) — required, because an unannotated lambda would infer `never` and silently uncheck its body. The data⇄look compatibility is a runtime contract by his explicit choice, not compile-checked. Heterogeneous storage is `Layer<unknown>`/`Look<unknown>` via method bivariance — CAUTION: a function-typed PROPERTY is strictly checked and breaks widening; keep D out of property positions. **Enum values are the backend's wire vocabulary, not descriptive names** — the lead corrected my `'geopotentialHeight'` to `'hgt'` (GRIB-style, 2026-07-13); ask him for the real wire name whenever a new Parameter lands, and keep the fixture backend's string checks in sync with it.
- **`Provider<I>`** (`objects/provider.ts`) is **one concrete class wrapping a `(grids: Grid[]) => I` function** — `new Provider((grids) => grids[0])`, `new Provider((grids) => Grid.combine(grids, Math.hypot))`. *Rejected: `Scalar`/`Derived`/`Vector` subclasses (overkill for now — can return if a named vocabulary pays off).*
- **`Look<I>`** holds its `provider` and a **pure typed `deckLayer(id, input: I)`**; the **engine** (`Overlay.draw`) does `look.deckLayer(id, look.provider.provide(grids))`, so the look never sees the grid list. *Rejected, in order: source-function-called-inside-deckLayer, a base `render(grids)` template (the lead: "look mustn't know the grid list"), a `Bound` wrapper class ("weird"), and a `Drawable` interface ("two classes for one thing").* There's **one `Look` type and no `any`**: a heterogeneous `Look<unknown>[]` holds `Look<Grid>`+`Look<[Grid,Grid]>` because `deckLayer` is a **method** (bivariant param) and `provider` is a **readonly** property (covariant return) → `I` is covariant.
- **`registry.ts` is a keyed object** `{ temperature: new Temperature(), … }` — the single source; ids are `keyof typeof layers` (write it inline at a serialization edge; no standing `LayerId` alias). **Layers are passed by instance** to `isShown`/`toggle` (singletons → reference identity; an id would just force a `layers[id]` lookup that the methods undo immediately). Ids only matter at persistence boundaries (URL/storage) — convert there.
- **Names live on the definitions now** (superseded 2026-07-13, multi-layer stacking): `Layer.name` (Hebrew) + per-look `{ look, name, checked }` entries — the layer-bar and hover readout both read them; the old menu-owns-names shape is gone. `checked` (renamed from `defaultOn` 2026-07-14) starts as the definition default and mutates in place as session memory of the checkbox state; `LookEntry` is also the activation unit (`activeLooks: Set<LookEntry>`). Look rows use the kind vocabulary ([[layer-menu-ux-taste]]). See [[one-service-per-domain]], [[httpresource-not-lazy-in-effect]], [[code-design-taste]].

**Wind look baseline approved (2026-07-05) — canvas trails (windy.com technique):** `TrailCanvas` (private class in `looks/wind-particles.ts`) simulates 2000 particles — distance-sampled crumb trails (16 crumbs, spacing scaled by speed → fast=long/slow=short), drain-out deaths (`dying` countdown shifts the trail out through the tail; no abrupt vanish), prime-stride cell spawning inlined in `spawn()` (7919 stride → even coverage) — and strokes them per-frame onto a `GeoCanvas`, rendered as `BitmapLayer`. Full clear+redraw each frame (accumulation-fade REJECTED: 8-bit alpha rounding leaves permanent residue). **Machinery in `engine/base/`** (looks/ = pure catalog, one file per look, mirrors layers/): `Look` contract; `AnimatedLayer` = rAF loop + `abstract step(dt)` + `abstract rebuild()` fired on deck's `changeFlags.propsChanged` (deck shallow-diffs props itself — no custom compare contract needed; Grids immutable → reference compare correct); `GeoCanvas` = bounds-sized **ping-pong canvases** (deck caches textures by image ref — alternating refs force re-upload) + `toX/toY` via `MercatorBand` (`utils/geo.ts`, merged mercator+bounds; `contains()` hand-written — Turf rejected for hot loops, GeoJSON alloc at 120k calls/s). **`TrailCanvas` must stay a separate class:** deck discards layer instances (every `Overlay.draw` → new instance) migrating only props+state — the canvas object in `state` is the survivor; merging into the layer = the rejected "weird mix of animation and deck functions". *Also rejected on the way: LineLayer segment trails (specks/flashing/uneven), verbatim 430-line GridParticles restore ("wtf are all these files"), streamline-comets (too sparse), dropping `Look` for direct deck construction in `layers/` (implemented then reverted — deck layers are disposable so a kept object must produce them, which IS `Look`).* Dev note: HMR leaves orphan rAF loops → page crawls to ~2fps after many hot-swaps; refresh clears; prod teardown correct.
